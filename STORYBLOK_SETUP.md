# Storyblok для Next Genium

## Что уже готово

- Astro умеет брать опубликованные главные страницы, новости и остальные страницы из Storyblok во время сборки.
- Пока ключей нет, сайт берёт существующие данные из проекта и собирает прежние 60 страниц.
- Новая опубликованная новость автоматически получает страницу `/news/<slug>/` или `/ru/news/<slug>/` и появляется в списке новостей.
- В редакторе подготовлены поля для заголовка, вступления, обложки, блоков текста, ссылок и SEO. Флажок «Показать на главной» управляет карточкой новости на главной странице.
- Скрипт импорта подготовит 2 главные страницы, 20 архивных новостей и 38 остальных страниц как **черновики**. Он не публикует их без редакторской проверки.

## Создать Space и подключить ключи

1. Space `geni` уже создан, Space ID `295769991716642` записан в локальный `.env`. Если Space создан вне EU, исправить `STORYBLOK_REGION` (`us`, `ca`, `ap` или `cn`).
2. В Space открыть **Settings → Access Tokens** и создать **Public** и **Preview** access tokens. В **My account → Account settings → Personal access tokens** создать отдельный токен для первоначального импорта через Management API. Ограничить его Space `geni` и правами **Components** и **Stories**.
3. В локальном `.env` заполнить `STORYBLOK_PUBLIC_TOKEN`, `STORYBLOK_PREVIEW_TOKEN` и `STORYBLOK_MANAGEMENT_TOKEN`. Токены не отправлять в чат и не публиковать. `.env` исключён из Git.
4. Проверить план импорта: `node scripts/storyblok-bootstrap.mjs`. Затем выполнить `node scripts/storyblok-bootstrap.mjs --apply`. Повторный запуск пропускает уже созданные схемы и истории; существующий контент не перезаписывается.
5. В Storyblok открыть черновики, вычитать тексты и изображения, затем публиковать нужные страницы. Архивные изображения ссылаются на путь `/site/assets/` нового сайта; новые картинки можно загружать в поле «Обложка» или «Загрузить изображение».

## Публикация на сайте

Сейчас сайт статический. Публикация в Storyblok меняет данные CMS, а публичный HTML обновится после новой сборки. Исходники уже подготовлены в `/opt/nextgenium-source` на Zomro и проверены локальной серверной сборкой. Скрипт `deploy/nextgenium-storyblok-deploy.sh` рассчитан на атомарную публикацию после добавления Public token в `/etc/nextgenium/storyblok.env`; без токена он отказывается менять сайт.

Автоматический запуск этого скрипта по webhook и защищённый предпросмотр черновиков надо включить после подключения токенов. Для Visual Editor Storyblok требует HTTPS-предпросмотр; статическая сборка показывает опубликованный контент только после пересборки. Живой предпросмотр черновиков потребует отдельного серверного режима. До его проверки редакторская панель и автоматическая публикация не считаются подключёнными.

Токены не добавлять в исходники, не отправлять в чат и не помещать в публичные HTML-файлы. Для боевой сборки используется только Public token. Preview token нужен для отдельного редакторского предпросмотра.

## Как это проверено без аккаунта

`node scripts/verify-storyblok-integration.mjs` запускает локальный подставной API, собирает сайт с изменённой главной, изменённой внутренней страницей и новой новостью, проверяет их HTML, после чего восстанавливает обычную сборку без CMS. Скрипт импорта проверен в режиме без записи: 8 моделей контента, 60 черновиков.
